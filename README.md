# publish-site-template

A GitHub **template repository** for publishing one frontend of a reproducible research
project as a public static website.

Use it when a project such as
[`absent-from-chronic`](https://github.com/RG-FIDES/absent-from-chronic) or
[`maelstrom`](https://github.com/RG-FIDES/maelstrom) contains at least one frontend
(`_frontend-1/`, `_frontend-2/`, …) whose rendered output should be publicly available.

> This README describes the template itself. `scripts/initialize-site.ps1` replaces it
> with a project-specific README the first time a frontend is imported.

## Why a separate repository

The source project holds private inputs, analysis code, and content sources. The public
website must hold none of those. Splitting them gives a hard, auditable boundary:

```
source project                              site repository (from this template)
------------------------------              -----------------------------------
data-private/       never leaves            _site/         only generated bytes
analysis/, manipulation/                    scripts/       the transfer harness
_frontend-N/content/   render here          site.config.json
_frontend-N/_site/  ────────────import────▶ _site/  ──push──▶  static host (no build)
```

Rendering always happens in the source project, where the private inputs live. This
repository has **no build step by design**.

## Using the template

### 1. Create the repository

On GitHub: **Use this template → Create a new repository**, in the `RG-FIDES`
organization. Name it after the source project with a `-site` suffix, for example
`absent-from-chronic-site`.

### 2. Render the frontend in the source project

```powershell
cd <source-project>/_frontend-1
quarto render
```

### 3. Import the frontend

Clone the new repository, open it in VS Code, and run the slash command:

```
/import-frontend C:\projects\absent-from-chronic\_frontend-1
```

The agent will dry-run the import, show you what it detected and what would be
transferred, confirm the site title, and then apply. Equivalent manual invocation:

```powershell
./scripts/initialize-site.ps1 -FrontendPath 'C:\projects\absent-from-chronic\_frontend-1'
./scripts/initialize-site.ps1 -FrontendPath 'C:\projects\absent-from-chronic\_frontend-1' -Apply
```

Initialization records `site.config.json`, renders `README.md` and `netlify.toml` from
`templates/`, and imports the artifact into `_site/`.

### 4. Connect a host

The artifact is served with no build step. On Vercel: Framework `Other`, Build Command
empty, Output Directory `_site`, Production Branch `main`. Alternatively enable GitHub
Pages against the `gh-pages` branch that `.github/workflows/deploy.yml` maintains.

### 5. Publish updates

Re-render in the source project, then in this repository:

```
/publish-site
```

or manually:

```powershell
./scripts/sync-site.ps1            # dry run
./scripts/sync-site.ps1 -Apply     # transfer
```

Review the diff, commit, and push. The host redeploys on push.

## What the template contains

| Path | Purpose |
| --- | --- |
| `scripts/initialize-site.ps1` | One-time binding to a frontend plus first import |
| `scripts/sync-site.ps1` | Audited, hash-verified artifact transfer |
| `scripts/lib/` | Shared function libraries for configuration and artifact inspection |
| `scripts/netlify-build.sh` | Netlify hook that verifies the artifact instead of building |
| `site.config.json` | Source project, frontend, and publish policy |
| `templates/` | `README.md` and `netlify.toml` rendered at initialization |
| `_site/` | The published artifact (empty until the first import) |
| `.github/prompts/` | `/import-frontend` and `/publish-site` slash commands |
| `.github/skills/publish-generated-site/` | Full procedure and policy reference for agents |
| `.github/instructions/` | Guardrail: never hand-edit generated files |
| `.github/workflows/deploy.yml` | Optional GitHub Pages mirror |
| `docs/publishing-model.md` | Design rationale and operational notes |

## Safety properties

`scripts/sync-site.ps1` is the only way content enters this repository. It:

- **refuses to publish** source files (`.qmd`, `.R`, `.Rmd`, notebooks, `.py`), data files
  (`.parquet`, `.sqlite`, `.db`, `.sav`, `.dta`), secrets (`.env`, `.pem`, `.key`), and
  caches (`.quarto`, `_freeze`, `_cache`, `data-private`);
- **warns** when configured sensitive strings appear inside generated HTML, CSS, JS, or JSON;
- **is a dry run by default** and requires `-Apply` to write;
- **refuses to delete** without `-AllowDelete`;
- **verifies byte-for-byte parity** with the source after every transfer, by SHA-256.

The policy lives in `site.config.json` under `publish`. Tighten it freely; loosening it
should be a deliberate, reviewed decision.

## Requirements

- Windows PowerShell 5.1 or PowerShell 7+
- Git (optional; used to detect the source project's remote URL)
- VS Code with GitHub Copilot, for the slash-command workflow
